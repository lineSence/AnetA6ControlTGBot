# UX/UI бота, версия 2.7.0

Документ описывает дизайн-систему бота, правила поведения экранов и чеклист
готовности к продакшн. Реализация: `tgbot/uxkit.py` (дизайн-система),
`tgbot/ui.py` (клавиатуры), `tgbot/handlers.py` (экраны),
`tgbot/middlewares.py` (доступ и антифлуд), `tgbot/main.py` (публикация меню).
Тесты: `tests/test_ux.py` (37 тестов).

## 1. Проблемы версии 2.6.0

| Проблема | Следствие |
| --- | --- |
| Разные форматы текста на экранах | пользователь не понимает, где он находится |
| Нет крошек и «Домой» на глубоких экранах | тупики, приходится жать `/menu` |
| Ответ на нажатие иногда терялся | Telegram показывал «часики» до таймаута |
| Ошибки уходили только в лог | пользователь видел «ничего не произошло» |
| Пустые списки без подсказки | непонятно, что делать дальше |
| Нет меню команд у поля ввода | функции бота не видны новичку |
| Двойное нажатие запускало действие дважды | лишние команды в очереди принтера |
| Чужой пользователь не получал ответа | выглядело как поломка бота |

## 2. Дизайн-система

### 2.1 Экран = четыре зоны

`uxkit.screen(title, body, path, meta)` собирает один шаблон:

1. **Заголовок** — жирный, с эмодзи. Одна строка.
2. **Тело** — до 8 строк вида `эмодзи Метка: значение` (`uxkit.field`).
3. **Крошки** — `uxkit.crumbs("пульт", "файлы")` → `пульт › файлы`, курсивом.
4. **Мета** — время обновления и TTL подтверждения, курсивом.

Меняющаяся мета даёт побочную пользу: Telegram не отвечает ошибкой
`message is not modified` при повторном обновлении. Остаток таких ошибок
глушит `uxkit.is_not_modified`.

### 2.2 Кнопки

- Подпись ≤ 22 символов (`MAX_LABEL`), длинную обрезает `clamp_label` с `…`.
- В ряду 2–3 кнопки. Четыре только для числовых пресетов температуры.
- Первичное действие — в первом ряду (`ui.state_row`).
- Последний ряд — навигация (`ui.nav_row`): `◀ Назад`, `🏠 Меню`, `🔄 Обновить`.
- Деструктивная кнопка не стоит рядом с навигационной.
- Тумблер показывает состояние подписью: `✅ Вентилятор` / `⬜ Вентилятор`.
- Псевдокнопки-подписи (счётчик страниц, текущее значение) ведут на `m:noop`,
  и обработчик отвечает на них пустым `ack`, чтобы не было «часиков».

### 2.3 Словарь эмодзи

| Эмодзи | Смысл |
| --- | --- |
| 🖨 📊 📷 | печать, статус, камера |
| 🌡 🛏 ❄️ | хотенд, стол, остудить |
| 🕹 🏠 ↔️ ↕️ | движение, парковка, шаги |
| 🎬 🧩 ⚙️ | анимации, макросы, тюнинг |
| ⚡ 🔄 🔁 🔃 ⛔ | питание и перезапуски |
| 🚨 | аварийный стоп |
| ✅ ⬜ ❌ | включено, выключено, отмена |
| ⏳ 🩺 🐞 ❓ | ожидание, диагностика, ошибки, помощь |

## 3. Навигация

- Один экран — одно сообщение. Переходы правят текущее сообщение
  (`uxkit.render`), а не плодят новые.
- Новое сообщение создаётся только для событий: аварийный стоп, уведомления
  WebSocket, длинные логи, медиа.
- «Домой» есть на каждом экране глубже второго уровня.
- Тупиков нет: тест `test_every_screen_has_an_exit` проверяет выход с каждой
  клавиатуры.

## 4. Реакция на нажатие

`answerCallbackQuery` вызывается ровно один раз через `uxkit.ack`. Три формы:

| Форма | Когда | Пример |
| --- | --- | --- |
| Пустой `ack` | переход между экранами | открыть «Файлы» |
| Тост (`ack(text)`) | результат понятен из экрана | `Хотенд → 215 °C` |
| Алерт (`ack(text, alert=True)`) | отказ или опасность | `Доступ закрыт` |

Операции дольше ~300 мс сначала рисуют плейсхолдер `⏳` (`handlers.loading`),
потом заменяют его результатом. Живой прогресс печати обновляется не чаще
одного раза в 5 секунд (`ws.live_update`), чтобы не попадать в лимиты Telegram.

## 5. Подтверждения

- Опасное действие открывает отдельный экран подтверждения. Алерт для этого
  не используется: в алерте не видно последствий.
- Безопасная кнопка (`❌ Отмена`) стоит слева, подтверждение — справа.
- В тексте перечислены последствия: что остановится, что перезапустится.
- Подтверждение одноразовое и живёт `pending_ttl_seconds`. Просроченное
  подтверждение возвращает пользователя на исходный экран с пояснением.
- Подтверждение требуется для: питания и перезапусков, опасных макросов,
  запуска печати, удаления анимации.

**Исключение: `🚨 Аварийный стоп` работает без подтверждения.** Это сделано
сознательно: при аварии важна одна секунда, а не лишний тап. Кнопка стоит
в отдельном последнем ряду, далеко от навигации. После остановки бот сам
показывает экран восстановления.

## 6. Пустые состояния и ошибки

- Пустой список файлов, макросов или анимаций показывает подсказку-кнопку:
  `❓ Как загрузить файл`, `❓ Что такое макросы`, `❓ Как добавить`.
- Ошибка рисует экран `handlers.error_screen`: заголовок, причина, кнопка
  `🔄 Повторить` на то же действие и выход домой.
- Глобальный обработчик `@router.errors` пишет ошибку в `errors.db` и сообщает
  пользователю: «Ошибка. Подробности в /errors». Молчаливых сбоев нет.
- Технические детали (логи Klipper, `/error <id>`) отправляются как обычный
  текст без HTML и режутся на части по 4096 символов.

## 7. Команды и меню

`main.publish_ui` при старте публикует список команд (`setMyCommands`) и
кнопку меню у поля ввода (`setChatMenuButton`). Ошибка публикации пишется
в лог и не мешает боту работать.

| Команда | Назначение |
| --- | --- |
| `/menu` | пульт принтера |
| `/status` | статус печати |
| `/files` | файлы и запуск |
| `/anims` | анимации на экране |
| `/errors` | последние ошибки |
| `/diag` | диагностика |
| `/help` | помощь по разделам |

Список короткий (7 команд) — так его видно целиком. Остальное доступно
кнопками. Текстовые синонимы (`меню`, `статус`, `файлы`, `помощь`) разобраны
в `handlers.COMMAND_ALIASES`, поэтому бот понимает и слова, и команды.
Неизвестный текст не игнорируется: бот показывает подсказку и кнопку меню.

## 8. Доступ и антифлуд

`tgbot/middlewares.py` ставит два слоя до обработчиков:

- `AccessMiddleware` — белый список `allowed_user_ids`. Чужому приходит алерт
  «Доступ закрыт», а подробное пояснение с его id — не чаще
  `deny_notice_seconds` (по умолчанию 300 с), чтобы бота нельзя было
  использовать как эхо.
- `AntiFloodMiddleware` — окно `antiflood_seconds` (по умолчанию 0.8 с) на
  пару «пользователь + действие». Второе нажатие получает тост
  «Секунду, обрабатываю…» и не доходит до принтера.

Словари обоих слоёв ограничены по размеру и чистятся, поэтому память не растёт.

## 9. Текст и форматирование

- Глобальный `parse_mode` не включён. HTML передаётся точечно, только там, где
  текст собран через `uxkit.screen`. Так технические логи нельзя случайно
  сломать разметкой.
- Все внешние данные (имена файлов, макросы, сообщения Klipper) проходят
  через `uxkit.esc`.
- Прогресс печати: `uxkit.progress` (полоса), `uxkit.pct` (процент),
  `uxkit.eta_seconds` (остаток). Ширина полосы настраивается
  (`progress_bar_width`, 4..20).

Чеклист собран по руководству gramio «UX patterns» и документации Telegram.

## 11. Тесты UX

`tests/test_ux.py` фиксирует дизайн-систему, поэтому регресс видно сразу:

- зоны экрана, экранирование HTML, крошки, обрезка подписей;
- полоса прогресса, процент, остаток времени;
- длина подписей и ширина рядов на всех 15 клавиатурах;
- выход с каждого экрана, отсутствие пустых и «мертвых» callback;
- пустые состояния с подсказкой, пагинация со счётчиком страниц;
- порядок кнопок в подтверждении;
- список команд и текстовые синонимы;
- доступ и антифлуд на фейковых событиях;
- новые ключи конфига и их безопасные границы.

## 12. Что осталось за рамками версии

- Роли пользователей (наблюдатель и оператор) вместо одного белого списка.
- Telegram Mini App для управления с графиками.
- Локализация: сейчас интерфейс только на русском.
- Инлайн-режим для быстрого статуса из любого чата.
