# Готовность к продакшн и рунбук (2.7.0)

Документ отвечает на два вопроса. Первый: готов ли бот к постоянной
работе. Второй: что делать, когда что-то пошло не так.

## 1. Где что лежит

| Объект | Путь |
| --- | --- |
| Код бота | `/root/tgbot/tgbot` |
| Конфиг | `/root/tgbot/config.yaml` (права 0600) |
| Виртуальное окружение | `/opt/tgbot` |
| Конвертер анимаций | `/root/gif2klipper.py` |
| Служба | `/etc/systemd/system/tg2printer.service` |
| Лог бота | `/var/log/tg2printer.log` |
| Лог установки | `/var/log/tg2printer_install.log` |
| Журнал ошибок | `/root/tgbot/errors.db` |
| Бэкапы обновлений | `/root/tgbot/backups/upgrade_<дата>` |
| Бэкапы анимаций | `/root/tgbot/backups/animations` |
| Конфиг Klipper | `/root/printer_data/config/printer.cfg` |

## 2. Чеклист перед запуском

1. `bot_token` заполнен, файл конфига имеет права 0600.
2. `allowed_user_ids` содержит только ваши id. Пустой список = бот никого
   не пускает.
3. `moonraker` доступен: `curl -s http://127.0.0.1:7125/printer/info`.
4. Если в Moonraker включён авторизация, задан `moonraker_api_key`.
5. `python` указывает на `/opt/tgbot/bin/python`, и в нём есть Pillow:
   `/opt/tgbot/bin/python -c "import PIL; print(PIL.__version__)"`.
6. Служба включена в автозапуск: `systemctl is-enabled tg2printer`.
7. Тесты прошли: `bash scripts/check.sh`.
8. В Telegram у бота видно меню команд и кнопка рядом с полем ввода.
9. `/diag` показывает версию 2.7.0, схему конфига 7 и живой WebSocket.

## 3. Обычные операции

| Задача | Команда |
| --- | --- |
| Состояние службы | `systemctl status tg2printer` |
| Перезапуск | `systemctl restart tg2printer` |
| Стоп | `systemctl stop tg2printer` |
| Живой лог | `journalctl -u tg2printer -f` |
| Лог файлом | `tail -n 200 /var/log/tg2printer.log` |
| Ошибки бота | в Telegram: `/errors`, детали `/error <id>` |
| Обновление | `git pull && sudo bash scripts/install.sh` |
| Обновление без тестов | `SKIP_TESTS=1 sudo bash scripts/install.sh` |

Установщик берёт версию из `tgbot/__init__.py`, поэтому версия в логе установки
всегда совпадает с версией кода.

## 4. Откат

Установщик сам делает бэкап перед обновлением и откатывается сам, если шаг
упал. Ручной откат:

```bash
systemctl stop tg2printer
ls -1 /root/tgbot/backups | tail -n 5      # выбрать upgrade_<дата>
B=/root/tgbot/backups/upgrade_20260910_120000
rm -rf /root/tgbot/tgbot && cp -a "$B/tgbot" /root/tgbot/tgbot
cp -a "$B/config.yaml" /root/tgbot/config.yaml
cp -a "$B/unit.service" /etc/systemd/system/tg2printer.service
systemctl daemon-reload && systemctl start tg2printer
```

Старые бэкапы чистятся автоматически. Глубина — `UPGRADE_KEEP` (по умолчанию 5).

## 5. Типовые проблемы

| Симптом | Причина и действие |
| --- | --- |
| Бот молчит на любое сообщение | служба не запущена или неверный токен. Смотреть `journalctl -u tg2printer -n 50` |
| «Доступ закрыт» у владельца | id не в `allowed_user_ids`. Узнать id командой `/whoami`, добавить в конфиг, перезапустить |
| Кнопки работают, но статус пустой | Moonraker недоступен. Проверить `/diag` и `systemctl status moonraker` |
| Нет живого прогресса печати | оборвался WebSocket. Бот переподключается сам; число попыток видно в `/diag` |
| Анимация не конвертируется | нет Pillow в venv или слишком большой файл. Проверить лимиты `animation_max_*` |
| Ошибки после обновления | откатиться по разделу 4 и прислать `/errors` |
| Служба крутится в перезапусках | systemd глушит цикл по `StartLimit`. Смотреть лог, чинить причину, потом `systemctl reset-failed tg2printer` |

## 6. Границы безопасности

- Доступ — только по белому списку. Чужие события отбрасываются до
  обработчиков.
- Действия питания и опасные макросы требуют подтверждения с ограниченным
  сроком жизни.
- Аварийный стоп выполняется сразу, без подтверждения. Так безопаснее.
- Критичные уведомления пробивают тихие часы (ключ
  `critical_alerts_ignore_quiet_hours`).
- Служба пишет только в разрешённые каталоги (`ReadWritePaths`).
- Токен и API-ключ можно держать в переменных `TG_BOT_TOKEN` и
  `MOONRAKER_API_KEY` вместо файла.

## 7. Мониторинг

Минимум для домашнего принтера:

- ежедневно смотреть `/diag` — там видны состояние Klipper, WebSocket
  и число ошибок;
- раз в неделю — `/errors`, чтобы ловить повторяющиеся сбои;
- проверять свободное место: `df -h /` и размер `/root/tgbot/backups`;
- после обновления Klipper или Moonraker — один тестовый запуск печати
  через бота.

## 8. Обслуживание данных

- `errors.db` сам хранит не больше `error_log_keep` записей.
- Словари состояния (подтверждения, сессии, антифлуд) чистит фоновая
  задача `janitor_loop`.
- Временные файлы превью удаляются после закрытия сессии.
- Бэкапы анимаций ограничены `animation_backup_keep`.

## 9. Что проверить на железе после 2.7.0

1. `/start` и `/menu` рисуют пульт, переходы правят одно сообщение.
2. Двойное быстрое нажатие одной кнопки даёт тост «Секунду, обрабатываю…».
3. Запуск печати требует подтверждения и показывает имя файла.
4. Нагрев и «Остудить всё» меняют цели и сразу обновляют экран.
5. Аварийный стоп останавливает принтер и предлагает восстановление.
6. Загрузка GIF даёт превью и применяется на экране принтера.
7. Ошибка Moonraker показывает экран с кнопкой «Повторить».
8. Перезагрузка хоста: служба поднимается сама, бот отвечает.

## 10. Известные ограничения

- Один уровень доступа: кто в списке, тот может всё.
- Связь с Moonraker идёт по HTTP в локальной сети. Для внешнего доступа
  нужен туннель или HTTPS-прокси.
- Камера отдаёт снимки, видеопотока нет.
- Автотесты проверяют логику без реального Telegram API и принтера.
- Файл CI лежит в `ci/ci.yml`. Его надо вручную скопировать в
  `.github/workflows/`, чтобы тесты шли на каждый пуш.
